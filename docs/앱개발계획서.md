# 앱 개발 계획서 — 장보기 → 냉장고 → 식탁 → 가계부 통합 앱

> 가칭: **"냉장고 집사"** (영문 가칭 FridgeMate)
> 작성일: 2026-10-12 · 버전 v0.1 (초안)

---

## 1. 개요

### 1.1 한 줄 정의
장 본 **영수증 한 장**으로 ① 냉장고 어디에 둘지 안내하고, ② 우리 가족 조건(아이 나이, 알레르기, 매운맛 금지 등)에 맞는 요리를 추천하며, ③ 품목별 구매 가격을 쌓아 "지난번보다 비싼지, 어느 마트가 싼지" 알려주는 앱.

### 1.2 해결하려는 문제
| 문제 | 현재 사용자 행동 | 불편 |
|---|---|---|
| 장 보고 와서 정리 | 감으로 냉장고에 넣음 | 보관 위치가 틀려 빨리 상함 (예: 사과 옆에 채소, 감자를 냉장 보관) |
| 오늘 뭐 해 먹지 | 레시피 앱 검색 → 재료가 없음 | 가지고 있는 재료와 가족 조건을 같이 따져 주는 앱이 없음 |
| 아이·가족 조건 | 레시피를 보고 머릿속으로 걸러냄 | 고춧가루, 견과류, 꿀(돌 전 영아) 같은 금지 재료를 매번 직접 확인해야 함 |
| 장바구니 물가 | 영수증을 버림, 가계부는 "마트 87,000원" 한 줄로 끝남 | 품목 단위로 가격을 비교할 수 없음 |

### 1.3 핵심 가치 (3+1)
1. **입고 자동화**: 영수증 / 온라인 주문내역 / 사진 → 식재료 자동 등록
2. **보관 위치 안내**: 우리 집 냉장고 구조에 맞춰 "채소칸 왼쪽", "냉동실 2단" 식으로 안내
3. **가족 맞춤 추천**: 가족 구성원별 **절대 금지(Hard)** / **선호(Soft)** 조건을 걸러낸 레시피, "이것만 사면 만들 수 있는 요리"
4. **품목 단위 가계부**: 당근 100g당 가격 추이, 마트별 비교, 공공 시세 대비 비싼지 싼지

```

     해외 PantryKeep │   ★ 우리 앱
     Shopmate        │  (영수증→재고→위치→가족레시피→가격이력)
                     │
 재고만 ─────────────┼──────────────▶ 레시피·가족 맞춤

                     │
```
**차별화 3가지**
1. **"넣을 때" 안내**: 경쟁 앱은 "언제 상하는지"만 알려줍니다. 우리는 "어디에, 어떻게 넣을지"까지 안내합니다.
2. **가족 Hard 제약**: LLM 추천 결과를 **규칙 엔진이 다시 검사**해서 금지 재료가 절대 섞이지 않게 합니다.
3. **"내 가격" 이력 + 공공 시세**: 단위 가격(100g당) 정규화, 마트별 비교, KAMIS·참가격 대비 비싼지 싼지 표시.

### 5.1 전체 아키텍처
```
┌──────────────── Client ────────────────┐
│ Android (Kotlin + Jetpack Compose)     │
│ PC Web  (Next.js / React)              │
│  - CameraX + ML Kit(온디바이스 1차 OCR)  │
│  - Room (오프라인 캐시)                  │
└───────────────┬────────────────────────┘
                │ HTTPS / JWT
┌───────────────▼────────────────────────┐
│ Backend API (FastAPI 또는 Supabase)     │
│  ├─ Receipt Service   영수증 파싱        │
│  ├─ Normalizer        품목/단위 정규화   │
│  ├─ Storage Advisor   보관 규칙 엔진     │
│  ├─ Recipe Service    추천 + 제약 검증   │
│  ├─ Price Service     가격 이력/비교     │
│  └─ Batch             KAMIS/참가격 수집  │
└──┬──────────┬──────────┬───────────────┘
   │          │          │
PostgreSQL  Object     외부 API
(+pgvector) Storage    - LLM (Claude / Gemini)
            (영수증)    - CLOVA OCR Receipt (선택)
                       - KAMIS, 참가격(공공데이터포털)
                       - 식약처 레시피/영양 DB
```

| PC | Next.js 웹 (반응형) | Compose Desktop | 가계부·식단은 웹이 배포·공유가 쉬움 |

| OCR | **멀티모달 LLM으로 영수증 이미지를 바로 구조화(JSON)** | CLOVA OCR 영수증 API (`/document/receipt`, 품목 items·할인·부가세 필드) ([NCP 문서](https://api.ncloud-docs.com/docs/en/ai-application-service-ocr-ocrdocumentocr-receipt)) | 실제 한국 영수증 50~100장으로 두 방식 정확도와 비용 비교(PoC) 후 결정 |

### 5.3 핵심 데이터 모델 (요약)
```
Household ─< Member (이름, 생년월일/월령, 매운맛 단계)
          │      └─< MemberConstraint (type: ALLERGY|AGE_BAN|DISLIKE|DIET, ingredient_tag, level: HARD|SOFT)
          ├─< StorageSpace (냉장고 A) ─< Compartment (냉장 1단, 채소칸, 도어, 냉동 2단 …)
          ├─< InventoryItem (표준품목, 수량, 단위, 칸, 입고일, 소비기한, 상태)
          ├─< Receipt (매장, 일시, 총액, 이미지) ─< ReceiptLine (원문명, 수량, 단가, 할인, 금액, 표준품목, 단위가격)
          └─< ShoppingList

Ingredient (표준품목 마스터: 당근, 대파 …)
   ├─ category, 알레르기 태그, 영아 금지 여부, 매운맛 여부
   ├─ StorageRule (보관온도대, 추천 칸 타입, 기본 소비기한, 손질 팁, 분리 보관 대상)
   └─ PublicPrice (KAMIS/참가격 일자별 시세)

Store (이마트 OO점, 쿠팡, 컬리 …)
Recipe ─< RecipeIngredient (표준품목, 양, 선택 여부, "아이 분리 가능" 플래그)
```

### 5.4 핵심 로직

**(1) 영수증 → 품목 정규화 파이프라인**
1. 이미지 전처리 (기울기 보정, 자르기) — 온디바이스
2. 멀티모달 LLM / CLOVA로 `{store, datetime, lines:[{raw_name, qty, unit_price, discount, amount}]}` 추출
3. 정규화: 규칙(정규식: `1kg`, `900ml`, `10입`) + 임베딩 매칭 + LLM 보조 → 표준품목, 용량(g/ml/개)
4. **단위가격** = (금액 − 할인) / 용량 × 100 → 100g(ml)당 가격으로 비교
5. 확신도가 낮은 항목은 검수 화면에서 강조 → 사용자 수정 내용을 학습 데이터(사전)로 축적

**(2) 보관 위치 추천 (규칙 엔진 우선)**
- `StorageRule`(품목 → 보관 온도대, 칸 타입) × 우리 집 `Compartment` 매핑 → 칸 추천
- 충돌 규칙: 에틸렌 발생 ↔ 민감 품목 분리, 생육 ↔ 즉석식품 분리(하단 배치)
- 규칙 데이터는 직접 구축(초기 약 300개 품목)하고, LLM은 **규칙에 없는 품목만** 보조 생성 → 사람이 검수 후 등록

**(3) 가족 맞춤 레시피 — 안전 설계 (가장 중요)**
```
후보 생성:  레시피 DB 검색(보유 재료 매칭률·임박도) + LLM 변형/생성
      ↓
Hard 필터 (규칙 엔진, LLM 아님):
   레시피 재료 → 표준품목 → 알레르기 태그 / 영아 금지 / 매운맛 태그
   하나라도 걸리면 → 제외 또는 "대체 재료 적용본"만 노출
      ↓
Soft 점수:  선호·기피, 조리 시간, 최근 먹은 메뉴 중복 감점
      ↓
결과 + "아이 몫 분리 시점" 안내
```
- LLM 출력은 반드시 **구조화(JSON) → 재료를 표준품목으로 재매핑 → Hard 필터 재검사**를 거칩니다.
- 앱 안에 고지: "알레르기 정보는 참고용이며, 가공식품 성분표를 꼭 확인하세요."

**(4) 가격 비교**
- 개인 이력: 같은 표준품목 + 비슷한 용량대의 단위가격 시계열
- 판정: 최근 N회 중앙값 대비 ±10% 이상이면 "비쌈/쌈" 배지
- 매장 비교: 매장별 최근 단위가격 중앙값
- 공공 시세: KAMIS 소매가(91개 품목, 135개 품종, 일별) 및 참가격 생필품 가격을 일 배치로 수집 → "전국 평균 대비" 표시

|---|---|---|---|
